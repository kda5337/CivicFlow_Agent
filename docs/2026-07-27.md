# 2026-07-27 작업 기록

## 요약

`rules.yaml`의 담당부서 규칙마다 `data_source`가 비어 있던("공백") IT지원팀·마케팅팀·행정팀·고객센터(주문/결제)·안전관리팀·법무팀·고객지원총괄팀 7개 부서에 대해, 새로 준비된 생성 데이터셋(`generated_*.json`, `sensitive_complaint_dataset.json`)과 `coupang_faq_order_payment.json`을 실제로 Supabase + Chroma(`chroma_merged_faq`)에 적재해 RAG 근거 공백을 메웠다. 각 데이터셋은 적재 전에 해당 부서 규칙의 키워드 커버리지와 내용 성격을 확인한 뒤 진행했고, 이 과정에서 `안전_사고_분류` 규칙이 "즉시 에스컬레이션이 우선"이라는 설계 의도와 달리 실제로는 `관리자검토필요` 플래그가 빠져 있던 버그를 발견해 추가했다(이로 인해 안전관리팀에 적재한 데이터는 실제로는 검색에 쓰이지 않는 상태로 남았다). 반대로 법무팀은 같은 설계 의도를 가졌지만 사용자 요청에 따라 라우팅은 그대로 두고 데이터만 채웠다. `sensitive_complaint_dataset.json`(고객지원총괄팀용)은 1차 검토 시 `민감민원` 규칙과 키워드가 겹쳐 죽은 데이터가 될 것으로 판단해 보류했으나, 사용자가 답변 내용을 사과 템플릿에서 절차/SLA 중심의 사실 정보로 대폭 보강한 뒤 재검토하는 과정에서, 실제로 이 데이터가 쓰이는 경로는 `민감민원`이 아니라 관리자검토필요가 없는 `기본_불만신고` fallback이며 라우팅 여부는 저장된 FAQ 문구가 아니라 그 순간의 실제 문의 텍스트로만 결정된다는 점을 바로잡아 최종적으로 적재했다. 부서 통합·삭제(안전관리팀 삭제, IT지원팀+회원관리팀 통합)도 논의됐으나 최종적으로는 진행하지 않고 기존 부서 구조를 그대로 유지했다. 새로 만든 ingest 스크립트 7개와 `retrieve.py`/`generate.py`/`rules.yaml`/`docs/intent-rule-dataset-design.md`를 함께 갱신했고, `chroma_merged_faq` 총 문서 수는 393건에서 1,052건으로 늘었다.

## sensitive_complaint_dataset.json → 고객지원총괄팀 (1차 보류 → 보강 후 적재)

- 1차 검토(105건, 전부 `관리자검토필요: true`)에서는 키워드 분포(불만/항의/신고/피해)가 `민감민원` 규칙 키워드와 정확히 일치하고, 답변도 "불편을 드려 죄송합니다" 류 사과 템플릿뿐이라 ingest하지 않기로 판단.
- 사용자가 답변 내용을 접수→담당부서 배정→처리중→답변완료 단계, 영업일 기준 SLA, 마이페이지 추적 방법 등 사실/절차 정보로 전면 보강(사과 문구 0건, 99건이 SLA 언급).
- 재검토 과정에서 라우팅 판단(`rules_node`)과 검색(`retrieve_node`)은 저장된 FAQ의 문구가 아니라 **그 순간 들어오는 실제 문의(raw_text)**만 기준으로 동작한다는 점을 재확인 — `민감민원`(관리자검토필요: true)에 걸리는 문의는 이 데이터와 무관하게 항상 RAG를 건너뛰지만, 문의유형은 불만/신고이면서 저 4개 키워드를 리터럴로 안 쓴 문의는 `기본_불만신고` fallback으로 빠져 정상적으로 `retrieve_node`를 타므로 이 데이터가 실제로 근거로 쓰인다.
- `backend/app/rag/ingest_sensitive_complaint_faq.py` 신규 작성 — Supabase(`sensitive_complaint_faq`, 원본의 `관리자검토필요` 값도 `review_required` 컬럼으로 문서화 목적 저장) + `chroma_merged_faq` 적재. "품질이 계속 별로인 것 같은데 어떻게 처리되나요"로 검색 테스트해 리터럴 키워드 없는 문의가 잘 검색되는 것을 확인.
- `rules.yaml`의 `기본_불만신고` `data_source`를 `sensitive_complaint_faq`로 갱신하면서, `민감민원`에서 잘못 복사되어 있던 "관리자 검토로 즉시 분기되어 RAG 자체를 건너뜀"이라는 부정확한 주석도 함께 정정.
