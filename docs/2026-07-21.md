## AI Hub 71844 데이터 추출 ("취소/반품/교환/환불/AS")

- 데이터셋 71844("민간 민원 상담 LLM 사전학습 및 Instruction Tuning 데이터")의 분류(classification) 라벨링 데이터에서 `consulting_category` 필드를 키워드로 필터링하는 방식 채택 (AI Hub의 "세부 분류 유형 분포" 정확한 매핑표는 로그인 필요한 데이터 설명서에만 있어 접근 불가했음).
- `data/ai_hub/extract_cancel_refund_data.py`: 3개 회사(액티벤처/엘지유플러스/하나카드) × Training/Validation 전체를 스캔.
  - 1차: 키워드 `["취소","반품","교환","환불","AS"]` → 738세션
  - 전체 120개 고유 카테고리를 직접 나열해보고 "해지"/"위약금"도 통신·카드사에서 실질적 취소 의미로 판단해 키워드 추가 → 998세션
  - AI Hub 공식 통계(1,629건/13.22%)와 대조하기 위해 **세션 단위**(전체 11,033세션, 14.76%)로 재계산 — 파일 단위(레코드 수)와 세션 단위(고유 상담건)가 다르다는 걸 확인.
  - "AS" 관련 카테고리가 문자 그대로는 없어서, 도난/분실·파손 관련 카테고리를 AS로 간주해 "분실" 키워드 추가 → **최종 1,556세션** (1,629와 4.5% 차이).

## 임베딩 모델을 OpenAI → 한국어 특화 오픈소스(KURE-v1)로 전환

- 기존 `text-embedding-3-small`(OpenAI)은 한국어 특화가 아닌 범용 다국어 모델임을 확인.
- 후보 비교: 업스테이지 Solar Embedding(API, 한국어 특화) vs `ko-sroberta-multitask`(자체 호스팅, 구식) vs `nlpai-lab/KURE-v1`(고려대 NLP&AI연구실, 자체 호스팅, 한국어 검색 벤치마크 SOTA급, 0.6B, 1024차원, 최대 8192토큰).
- **KURE-v1 채택** — 무료·완전 자체 호스팅 요구사항에 부합.
  - `backend/app/rag/vectorstore.py`: `OpenAIEmbeddings` → `HuggingFaceEmbeddings(model_name=...)`
  - `backend/app/core/config.py`: `openai_api_key` 필드 삭제, `embedding_model` 기본값을 `nlpai-lab/KURE-v1`로 변경
  - `requirements.txt`: `langchain-openai` 제거, `langchain-huggingface` + `sentence-transformers` 추가
  - `.env`/`.env.example`/`README.md`: OpenAI 관련 내용 전부 제거
  - 실제로 `OPENAI_API_KEY` 없이 벡터스토어 생성 및 임베딩이 정상 동작함을 확인.

## `ingest_cancel_refund.py`: Supabase + Chroma 적재 파이프라인

- 처음엔 요약(summary) instruction의 output을 LLM에 넣어 질문을 생성하는 방식으로 시작했으나, **"질문/답변 모두 LLM 가공이 있으면 안 된다"**는 요구사항에 따라 전면 수정.
  - `extract_turns(consulting_content, speaker)`: 상담 원문("고객: .../상담사: ...")에서 지정한 화자 발화만 그대로 추출하는 순수 문자열 처리 함수로 교체. `speaker="customer"`가 질문, `"counselor"`가 답변.
  - **버그 발견**: 첫 빌드에서 1,556세션 중 269건만 성공(83% 유실). 원인은 **하나카드가 고객을 "손님:"이라고 표기**(액티벤처/엘지유플러스는 "고객:")하는데 정규식이 "고객"만 인식했기 때문. 전체 데이터를 스캔해 라벨이 `상담사`/`손님`/`고객` 3개뿐임을 확인 후 "손님"도 고객으로 인식하도록 수정 → 1,556/1,556 전부 성공.
- 3단계 파이프라인으로 구성 (`build` → `load-supabase` → `load-chroma`), 각각 독립 실행 가능.
  - `build_qa_pairs()`: 세션별 질문/답변을 `cancel_refund_qa_pairs.json`으로 저장 (DB 미접촉).
  - `ingest_supabase()`: `cancel_refund_faq` 테이블(`ensure_table()`로 없으면 자동 생성) 에 upsert. Chroma 미접촉.
  - `ingest_chroma()`: Supabase에서 `(source, source_id)`로 `id`를 재조회해, 질문만 임베딩 후 Chroma에 저장 (`metadata.supabase_id`로 역참조 가능하게).
  - 두 함수 다 `--dry-run`으로 소량 시험 가능.
- 실행 결과: Supabase `cancel_refund_faq`에 1,556행(하나카드 1,287 / 엘지유플러스 249 / 액티벤처 20) 적재 확인.

## 경로 문제 디버깅 및 수정

- IDE의 "실행" 버튼(파일 직접 실행)으로 돌리면 `ModuleNotFoundError: No module named 'app'` 발생 → `ingest_cancel_refund.py` 상단에 `backend`를 `sys.path`에 강제로 넣는 보정 코드 추가.

  - `.env`/`.env.example`에서 이제 안 쓰는 `CHROMA_PERSIST_DIR` 줄 삭제.
  - 재현 테스트로 리포 루트에서 실행해도 `backend/chroma_db`의 진짜 데이터를 정확히 찾는 것을 확인, 잘못 생성됐던 빈 폴더는 삭제.
