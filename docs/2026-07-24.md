# 2026-07-24 작업 기록

## 요약

백엔드를 재기동하는 과정에서 이전 세션의 죽지 않은 좀비 프로세스와 포트 충돌을 발견해 정리했고, `psycopg2-binary`/`langchain-huggingface` 등 실제로는 설치돼 있지 않던 의존성을 `requirements.txt` 기준으로 전부 설치했다. Streamlit 프론트엔드(`frontend/app.py`)에 답변 위에 사용자 입력, 관련여부와 판단 이유, 문의유형, 담당부서 후보, 최종 담당부서, 우선순위를 보여주는 처리 과정 섹션을 추가했다. 쿠팡 FAQ 데이터셋에 어느 PDF 파일의 몇 번째 질문인지(`source_pdf_file`/`source_pdf_question_number`), PDF에 없는 항목은 원본 URL(`source_pdf_note`)을 보여주도록 `coupang_faq` 테이블에 컬럼을 추가하고 Supabase에 재적재했다. 같은 맥락에서 면세점 FAQ 테이블(`duty_free_faq`)에도 공공데이터셋 번호와 이름, 자주묻는질문타입별 순번을 저장하는 컬럼 3개를 추가해 답변 각주에 정확한 출처가 뜨도록 했다. `retrieve.py`가 이 두 테이블의 값을 조합해 사람이 읽기 좋은 출처 라벨(PDF명+번호, URL, 공공데이터셋명+타입+순번)을 만들도록 수정했다. RAG가 top-3 대신 가장 유사도 높은 문서 1개만 LLM에 근거로 넘기도록 `RAG_TOP_K`를 1로 낮췄다. 특정 질문이 아무 근거 없이 LLM 혼자 답변을 지어내는 걸 발견해 추적한 끝에, 기본 검색 대상이던 `knowledge_base` 컬렉션이 처음부터 비어 있었다는 근본 원인을 찾았다. 이를 해결하기 위해 `retrieve_node`가 문의유형이나 매칭된 Rule과 무관하게 항상 실제 데이터(면세점+쿠팡)가 있는 `chroma_merged_faq`를 검색하도록 단순화했다. 작업 도중 오늘 여러 번 재시작하며 남은 uvicorn 좀비 프로세스와, 2026-07-22부터 계속 떠 있던 Streamlit 프로세스를 발견해 정리했고, 프로젝트에 별도 `.venv`가 있다는 것도 확인했다.

## 백엔드 재기동 문제 해결

- 포트 8000에 이전 세션의 uvicorn 프로세스가 남아 있어 새로 띄운 서버와 충돌(`WinError 10013`)했다. 그 프로세스가 오늘 수정하기 전의 옛 코드(옛 규칙 이름 `취소환불_분류`, 옛 담당부서명)를 그대로 실행 중이었다는 것도 실제 요청으로 확인해 종료했다.
- 재기동 시도마다 `psycopg2`, `langchain_huggingface` 모듈이 없어 계속 실패 — `requirements.txt`에는 있지만 이 환경에 실제로 설치돼 있지 않았던 것. `pip install -r requirements.txt`로 전체 설치했고, 이 과정에서 `huggingface-hub`/`transformers`/`streamlit`이 전역 환경에서 다운그레이드된 것을 확인해 사용자에게 알렸다.
- uvicorn의 `--reload`가 이 환경에서 코드/설정 변경 후 "Reloading..."만 찍고 실제로 워커를 교체하지 않는 현상을 여러 번 재현했다. 이후로는 `--reload` 없이 띄우고, 코드를 고칠 때마다 수동으로 프로세스를 종료·재시작해 확인하는 방식으로 바꿨다.

## 프론트엔드: 처리 과정 표시 추가

- `frontend/app.py`에 답변 앞에 "처리 과정" 섹션을 추가: 사용자 입력, 관련여부, 관련여부 판단 이유, 문의 유형, 담당부서 후보(`rule_flags.candidate_departments`), 최종 선정 담당부서, 우선순위를 순서대로 표시.
- `classification`이 없는 경우(intake에서 관련없음으로 거부된 입력)엔 이 블록 전체를 건너뛰고 관련여부·판단이유까지만 보여주도록 분기.

## 쿠팡 FAQ 출처 세분화

- `data/knowledge_base/coupang_faq_combined.json`이 이미 `source_pdf_file`/`source_pdf_question_number`(업로드된 6개 PDF 중 어느 파일의 몇 번째 질문인지)와, PDF에 없는 항목을 위한 `source_pdf_note`를 담고 있는 것을 확인.
- `backend/app/rag/ingest_coupang_faq.py`: `ensure_table()`에 이 3개 컬럼을 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`로 추가, `upsert_faq()`가 채우도록 수정.
- `db/schema.sql`에 지금까지 빠져 있던 `coupang_faq` 테이블 정의를 새 컬럼까지 포함해 추가.
- 테이블을 삭제하지 않고 `load-supabase`로 UPSERT 재적재(`id` 유지 → Chroma의 `supabase_id` 참조가 안 깨짐), 65건 전부 갱신 확인. 이어서 `chroma_coupang_faq` 임베딩도 함께 재생성됨.
- `backend/app/graph/nodes/retrieve.py`에 `_fetch_faq_row()`를 추가해, PDF 유래 항목은 "파일명 N번 질문"으로, PDF에 없는 항목은 `source_url`을 그대로 출처로 보여주도록 수정.

## 면세점 FAQ 출처 세분화

- `duty_free_faq` 테이블은 이미 `source`/`faq_type`/`faq_id` 컬럼이 있었지만, `source`가 "data.go.kr:제주면세점_FAQ"로 축약돼 있어 정확한 데이터셋 번호·공식명이 안 보였다.
- `backend/app/rag/ingest_duty_free_faq.py`에 `DATASET_ID`("15118694")/`DATASET_NAME`("제주관광공사_온라인면세점 자주묻는 질문") 상수와, `assign_faq_type_index()`로 `faq_type`별 1부터 순번을 매기는 함수를 추가. `ensure_table()`/`upsert_faq()`에 `source_dataset_id`/`source_dataset_name`/`source_faq_type_index` 컬럼 반영.
- `db/schema.sql`의 `duty_free_faq` 정의에 새 컬럼 3개 추가.
- `load-supabase` 재실행으로 30건 전부 UPSERT 갱신(테이블 삭제 없음) — 이용방법 14건이 1~14번으로, 나머지 타입도 각자 순번대로 정확히 채워진 것을 DB에서 직접 조회해 확인.
- `retrieve.py`의 `_fetch_faq_row()`에 `duty_free_faq` 분기를 추가해 "공공데이터포털(15118694) 제주관광공사_온라인면세점 자주묻는 질문 - 환불취소문의 1번째 질문" 형태의 라벨을 조립하도록 수정, 실제 요청으로 확인.

## RAG top_k 3 → 1

- 답변 하나에 근거 문서가 3개까지 뜨는 게 `RAG_TOP_K=3` 설정 때문임을 확인.
- LLM에 실제로 넘어가는 근거(`_format_context`)와 화면에 보여주는 출처 각주(`_format_sources_footer`)가 `retrieved_docs`라는 같은 리스트를 그대로 쓴다는 것도 함께 확인.
- 가장 유사도 높은 1개만 넘기고 싶다는 요청에 따라 `.env`, `.env.example`, `backend/app/core/config.py`의 `RAG_TOP_K`/`rag_top_k`를 전부 `1`로 변경.

## `knowledge_base` 빈 컬렉션 발견과 `retrieve_node` 단순화

- 결제_정산_분류(취소/환불 키워드)에 안 걸리는 질문(예: "면세점에서 상품을 사려면 뭐가 필요해?")이 아무 근거 없이 LLM 혼자 그럴듯한 답변을 지어내는 것을 실제 Streamlit 화면과 API 응답(`retrieved_docs: []`)으로 확인.
- 원인 추적 결과 기본 검색 대상이던 `knowledge_base` Chroma 컬렉션이 `vs._collection.count()` 기준 **0건** — 애초에 아무것도 적재된 적이 없었다.
- `backend/app/graph/nodes/retrieve.py`에서 `_MERGED_FAQ_RULES`/`COLLECTION_NAME` 기반 조건부 분기를 제거하고, `retrieve_node`가 문의유형·매칭된 Rule과 무관하게 항상 `chroma_merged_faq`(면세점 30건+쿠팡 65건, 실제 데이터가 있는 컬렉션)를 검색하도록 단순화.
- 같은 질문으로 재확인한 결과, 면세점 FAQ("이용방법 5번째 질문")를 근거로 신분증 종류 등 구체적인 내용을 답변하고 출처도 정확히 표시되는 것을 확인. `knowledge_base`에 나중에 실제 문서가 채워지면 조건부 분기를 되살리면 된다는 점을 코드 주석으로 남김.
