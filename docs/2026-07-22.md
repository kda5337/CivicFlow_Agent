# 2026-07-22 작업 기록

## 요약

기존 `duty_free_faq`(제주 면세점) 적재 파이프라인에 어느 데이터셋에서 온 값인지 알 수 있는 `source` 컬럼과 Chroma 임베딩 진행률(tqdm) 표시를 추가한 뒤, `data/knowledge_base`에 이미 있던 쿠팡 뉴스룸 FAQ 원본 3종(환불/취소·교환·반품/이용정책, 답변이 dict로 세분화된 것 포함)을 하나의 질문-답변 JSON으로 합치는 `build_coupang_faq.py`와, 이를 Supabase(`coupang_faq`, 답변 저장)+Chroma(`chroma_coupang_faq`, 질문만 임베딩) 구조로 적재하는 `ingest_coupang_faq.py`를 새로 만들어 실제 65건을 적재했다. 이어서 `chroma_duty_free_faq`와 `chroma_coupang_faq` 두 컬렉션을 `chroma_merged_faq` 하나로 합치면서(`source_table` 메타데이터로 어느 Supabase 테이블을 봐야 하는지 구분) 원본을 안전하게 삭제하고, 그 과정에서 남은 Chroma 디스크상의 고아 세그먼트 폴더 2개까지 백업 후 정리했다. 그래프 쪽에서는 `manual_review` 관련 이름을 전부 `manager_review`로 바꾸고, `retrieve_node`가 `취소환불_분류` Rule에 걸리면 `knowledge_base` 대신 `chroma_merged_faq`+Supabase 역참조로 검색하도록 분기를 추가했으며, `generate_node`가 LLM 답변 뒤에 실제 참고한 근거를 코드로 직접 붙이는 출처 각주 기능도 넣었다. 전체 그래프를 노드 단위로 실제 실행해 추적하는 과정에서, `intake_node`의 관련성 판별이 "대학교 학사행정"으로만 하드코딩되어 있어 쿠팡류 질문이 전부 거부되는 것을 발견했고, 프롬프트뿐 아니라 LLM에 실제로 전달되는 Pydantic `Field(description=...)`까지 같이 고쳐야 한다는 것과, 문구를 잘못 좁히면 졸업요건 질문이 회귀로 거부되거나 "민원"이라는 단어를 LLM이 좁게 해석해 같은 입력에도 판정이 들쭉날쭉해지는 문제가 있다는 것을 반복 테스트로 확인하며 프롬프트를 안정화시켰다. 마지막으로 Node.js가 설치되어 있지 않은 환경 제약 때문에 계획했던 React 대신 Streamlit으로 입력창+답변만 있는 최소 프론트엔드를 만들고, 백엔드(uvicorn)와 함께 직접 띄워 실제 질문으로 끝까지 동작을 확인했다.

## `duty_free_faq` 출처 컬럼 + Chroma 진행률

- `backend/app/rag/ingest_duty_free_faq.py`: `DATASET_SOURCE` 상수 추가, `ensure_table()`에 `source` 컬럼(신규 `CREATE TABLE`과 기존 테이블 대비 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 둘 다) 반영, `upsert_faq()`가 이 값을 채우도록 수정.
- `ingest_chroma()`의 "Supabase 조회"/"Chroma 임베딩" 루프를 주기적 `print` 대신 `tqdm` 진행 바로 교체 (`requirements.txt`에 `tqdm` 추가).
- 실제로 `fetch` → `load-supabase` → `load-chroma` 전체 실행 (30건), Supabase/Chroma에 저장된 실제 로우·문서를 직접 조회해 저장 형식(답변은 Supabase에 원문 그대로, Chroma는 질문만 1024차원 임베딩 + `metadata.supabase_id`로 역참조) 확인.

## 쿠팡 FAQ 통합 데이터셋 (`build_coupang_faq.py`)

- 처음엔 `https://news.coupang.com/archives/64201/`을 직접 스크래핑하는 방향으로 접근했으나(WebFetch/requests+bs4로 실제 HTML 구조 확인 시도), 사용자가 중단을 요청 — 대신 `data/knowledge_base/refund_faq.json`, `exchange_return_faq.json`, `return_policy.json`(이미 존재하던 원본 3종)을 기준으로 다시 시작.
- `refund_faq.json`/`exchange_return_faq.json`은 답변이 이미 문자열 하나, `return_policy.json`은 `steps`/`notes`/중첩 dict·list로 세분화되어 있음을 확인.
- `flatten_answer()`: 세분화된 답변(dict/list)을 "키: 값" / "- 항목" 형태로 순서대로 이어붙여 하나의 문자열로 합치는 함수 작성 (요약·재작성 없이 원문 그대로).
- `build()`: 3개 원본 파일을 순회해 `id`/`category`/`question`/`answer`/`source_file`/`source_url`/`published_date` 필드를 가진 65건(환불 8 + 취소/교환/반품 51 + 이용정책 6)을 `data/knowledge_base/coupang_faq_combined.json`으로 저장.

## 쿠팡 FAQ Supabase + Chroma 적재 (`ingest_coupang_faq.py`)

- `ingest_duty_free_faq.py`와 동일한 구조로 작성: `coupang_faq` 테이블(`ensure_table`/`upsert_faq`) + `chroma_coupang_faq` 컬렉션, `load-supabase`/`load-chroma`/`test` 명령, tqdm 진행 바 포함.
- 사용자가 인자 없이 파일을 직접 실행해 `load-supabase`(기본값)만 실행되고 Chroma는 안 들어간 상황을 확인해 `load-chroma`를 별도로 안내.
- 이후 "Supabase에 들어간 출처를 공식 쿠팡 정책이라고 수정해달라"는 요청에 따라 `DATASET_SOURCE = "공식 쿠팡 정책"` 상수를 추가하고 `upsert_faq()`가 `record["source_file"]` 대신 이 값을 쓰도록 변경 (기존 65건은 `ON CONFLICT DO UPDATE`로 재실행 시 갱신됨).

## Chroma 컬렉션 병합 및 디스크 정리

- `merge_chroma_faq.py`: `chroma_duty_free_faq`+`chroma_coupang_faq`의 문서/메타데이터/임베딩을 그대로 복사(재임베딩 없음)해 `chroma_merged_faq`로 합치고, 각 문서에 `source_table`(`duty_free_faq`/`coupang_faq`) 메타데이터를 추가해 이후 Supabase 역참조 시 어느 테이블을 봐야 하는지 구분되게 함.
- 원본 컬렉션은 복사 직후 대상 컬렉션에 실제로 같은 건수가 들어갔는지 확인한 뒤에만 삭제하도록 안전장치를 넣고(하나가 실패해도 다른 하나까지 지우지 않음) 실행 — 95건(30+65) 병합 확인.
- 삭제 후에도 `backend/chroma_db` 아래에 세그먼트 폴더 2개가 남아있는 것을 발견 — `chroma.sqlite3`의 `collections`/`segments` 테이블을 직접 조회해 두 폴더가 현재 어떤 컬렉션에도 참조되지 않는 고아 상태임을 확인한 뒤, `chroma_db` 전체를 스크래치 디렉토리에 백업하고 나서 폴더 2개를 삭제. 삭제 후 남은 컬렉션(`chroma_merged_faq`/`chroma_cancel_category`/`knowledge_base`) 전부 정상 로드 확인.

## LangGraph 노드 이름 변경: `manual_review` → `manager_review`

- 파일명(`manual_review.py`→`manager_review.py`), 함수명(`manual_review_node`→`manager_review_node`), 그래프 노드 키/라우팅/엣지(`backend/app/graph/build.py`), 플래그명(`requires_manual_review`→`requires_manager_review`, `rules.py`/`state.py`), status 값(`urgent_manual_review`→`urgent_manager_review`, `state.py`/`db/schema.sql`), Langfuse span 이름(`escalate-to-manual-review`→`escalate-to-manager-review`), `README.md` 관련 설명 3곳까지 전부 일괄 변경.
- 변경 후 `get_compiled_graph()`가 정상 컴파일되고 노드 목록에 `manager_review`가 정확히 반영되는 것을 확인.

## `retrieve_node`: `취소환불_분류` → `chroma_merged_faq` 라우팅

- `backend/app/graph/nodes/retrieve.py`에 `MERGED_FAQ_COLLECTION_NAME = "chroma_merged_faq"`, `_MERGED_FAQ_RULES = {"취소환불_분류"}` 추가.
- `rule_flags.matched_rules`에 `취소환불_분류`가 있으면 `knowledge_base` 대신 `chroma_merged_faq`에서 검색하고, 결과의 `metadata.source_table`로 Supabase(`duty_free_faq`/`coupang_faq`) 답변을 역참조하는 `_retrieve_from_merged_faq()` 추가. 테이블명은 `_FAQ_ANSWER_TABLES` 화이트리스트로 검증 후에만 SQL에 사용(인젝션 방지).
- 실제 상태 객체로 직접 호출해 정상 동작 확인 (쿠팡 FAQ 3건이 정확히 검색되고 답변이 역참조됨).

## `generate_node`: 답변에 출처 각주 추가

- 프롬프트 수정 대신, LLM 응답 뒤에 `retrieved_docs`를 코드가 직접 순회해 만드는 "참고 자료" 목록을 붙이는 방식 채택 — LLM이 실제로 안 쓴 근거를 지어내거나 누락할 위험을 없애기 위함.
- `_friendly_source_label()`: 내부 식별자(`coupang_faq:1`, `duty_free_faq:*`, `curriculum_db(SQL)`)를 사람이 읽기 좋은 라벨로 변환, `knowledge_base` 문서(파일명)는 그대로 표시.
- `_format_sources_footer()`: 중복 출처 제거, `retrieved_docs`가 비어있으면 아무것도 안 붙임.
- 실제 LLM 호출로 각주가 정확히 붙는 것을 확인.

## 전체 파이프라인 트레이스로 발견한 관련성 판별 버그

- `backend/scratch_test_nodes.py`에 `trace_graph(text)` 함수를 추가해 컴파일된 그래프를 실제로 실행하며 각 노드 결과와 최종 `draft_answer`까지 확인.
- **발견 1**: "반품하면 언제 환불되나요?" 같은 쿠팡류 질문이 `intake_node`에서 관련없음으로 거부됨 — `RELEVANCE_PROMPT`가 "대학교 학사행정 민원·문의"로만 범위를 한정하고 있었기 때문. 프롬프트를 "민원·문의 접수 시스템"으로 넓게 수정.
- **발견 2**: 프롬프트만 고쳐도 판정이 안 바뀜 — 실제 원인은 `backend/app/models/schemas.py`의 `RelevanceCheckResult.관련여부` `Field(description=...)`에 "학사행정 민원·문의(...)" 문구가 하드코딩되어 있었고, 이 설명이 구조화 출력 스키마의 일부로 LLM에 그대로 전달되고 있었음. 이것도 함께 수정.
- **발견 3(회귀)**: 넓히는 과정에서 "졸업요건/교육과정" 예시를 프롬프트에서 빼버려 대학 졸업요건 질문까지 거부되는 회귀 발생 — 예시 목록에 다시 포함해 해결.
- **발견 4(불안정성)**: "민원"이라는 단어를 LLM이 "개인 피해 신고"로 좁게 해석해, 같은 쿠팡 반품 질문도 호출마다 관련여부가 True/False로 들쭉날쭉함(temperature=0인데도) — "~하면 언제 되나요" 같은 절차·정책 문의도 포함된다는 문구를 추가하고, 무관한 것으로 볼 케이스(날씨/음식 추천 등)를 구체적으로 한정해 3회 반복 테스트로 안정화 확인.
- 수정 후 최종 확인: 쿠팡 반품 질문(→ `취소환불_분류` → `chroma_merged_faq`), 대학 졸업요건 질문(→ `졸업요건_문의` → `curriculum_lookup`), 잡담(→ `reject`) 세 케이스 모두 정확히 처리됨.
- `trace_graph()`를 입력/최종 답변만 출력하도록 단순화하고, 더 이상 안 쓰는 `curriculum_queries` 수동 테스트 블록과 그로 인한 미사용 import(`curriculum_lookup_node`, `rules_node`)를 삭제해 스크립트 정리.

## 프론트엔드: Streamlit 최소 화면

- 이 환경에 Node.js가 설치되어 있지 않아, `frontend/README.md`에 계획된 React 대신 Streamlit으로 최소 화면(입력창 + 버튼 + 답변)을 구현하기로 변경.

- 백엔드(`uvicorn app.main:app`, 8000번)와 Streamlit(8501번)을 실제로 띄우고, 실제 질문("반품하면 언제 환불되나요?")으로 끝까지 정상 응답되는 것을 확인.
