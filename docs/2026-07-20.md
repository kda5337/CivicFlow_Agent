# 2026-07-20 작업 기록

## 요약

AI Hub API 연동(데이터셋 목록/실제 데이터 조회)과 RAG 파이프라인의 PDF 처리(목차 파싱, 스캔본 OCR)를 먼저 구축한 뒤, 22학번 커리큘럼·졸업요건 데이터를 정규화된 스키마로 설계해 Supabase(PostgreSQL)에 실제로 적재·검증했고, 마지막으로 `rules.yaml`에 졸업요건/교육과정 문의 규칙을 추가하고 이 규칙이 매칭되면 LLM이 생성한 SQL로 Supabase를 직접 조회해 답변 근거로 쓰는 `curriculum_lookup_node`를 새로 구현했다. 구현 과정에서 SQL 서브쿼리 오류, intake 관련성 판별이 새 문의 유형을 걸러내던 문제, 답변 생성 시 맥락 손실 문제를 실제 테스트로 찾아 모두 수정했고, 전체 흐름과 스크립트 테스트로 정상 동작을 확인했다.

## RAG 파이프라인 (`backend/app/rag/`)

- `ingest.py`: `from langchain.text_splitter import RecursiveCharacterTextSplitter` → `from langchain_text_splitters import RecursiveCharacterTextSplitter`로 수정.
  - 설치된 langchain(1.3.11)에서 `langchain.text_splitter` 모듈이 완전히 제거되고 `langchain_text_splitters` 패키지로 이전됨.
- `pdf_toc.py` (신규): PDF 목차(TOC) 페이지를 파싱해 쪽수로 소속 섹션을 조회하는 유틸리티.
  - `extract_pages_text(pdf_path, page_numbers)`: pypdf로 지정한 쪽만 직접 추출 (전체 문서를 읽을 필요 없음).
  - `parse_toc(text)`: "제목 + 점 리더 + 쪽수" 형태의 목차 줄을 정규식으로 파싱.
  - `build_page_lookup(entries)`: 쪽수 → 소속 섹션을 찾는 `section_for_page()` 함수 반환 (bisect 기반).
  - 실제 목차 이미지 확인 후, 점 리더가 ASCII 마침표(`.`)가 아니라 가운뎃점(`·` 등) 계열 문자임을 발견하여 정규식(`LEADER_CHARS`) 수정.
- `ocr_toc.py` (신규): `data/self_collected/2022 가천대학교 요람 (총람).pdf`가 텍스트 레이어 없는 스캔 PDF임을 확인(274쪽 전체 텍스트 추출 0건) —
  PyMuPDF(`fitz`)로 페이지를 이미지 렌더링 후 `pytesseract`로 OCR. 11, 12쪽 내용을 출력.
  - Tesseract OCR 엔진 및 한국어 언어팩은 시스템에 별도 설치 필요 (사용자가 직접 설치 예정).

## OCR (pytesseract) 테스트

- Tesseract OCR 엔진(+한국어 언어팩) 설치 후 `ocr_toc.py`로 실제 11, 12쪽 재테스트.
  - 12쪽은 대체로 정상 인식, 11쪽(점 리더가 빽빽한 목차 페이지)은 노이즈 심함.
  - `zoom`(렌더링 해상도) 상향, `--psm 4`/`--psm 6` 페이지 세그멘테이션 모드 변경을 시도했으나 근본 개선 안 됨 — 점 리더를 Tesseract가 한글 글자로 오인식하는 게 원인. 이미지 전처리(점 리더 제거)가 필요하나 보류.
- Vision LLM(이미지를 통째로 LLM에 넘겨 텍스트 추출)도 검토. 현재 채팅 LLM인 업스테이지 Solar Pro는 이미지 입력을 지원하지 않아, 도입하려면 OpenAI 비전 모델(이미 `OPENAI_API_KEY` 있음) 등 별도 모델이 필요함을 확인. 실제 도입은 보류.

## 22학번 커리큘럼 DB 설계 및 Supabase 적재

- `db/schema.sql`에 `graduation_requirements`(학번별 졸업 이수학점 기준), `curriculum_courses`(학번별 개별 교과목, `requirement_id`로 전자를 FK 참조) 테이블 추가.
  - 트랙(Language-AI/Vision-AI)·학년·학기가 다른 과목은 별도 컬럼(`track`, `year`, `semester`)으로 표현, 소계/학과편성학점 같은 집계값은 저장하지 않고 쿼리로 계산하도록 설계.
- `db/seed_curriculum_2022.sql`: 22학번 실제 커리큘럼 데이터 전체를 INSERT문으로 작성.
  - `pglast`(PostgreSQL 파서)로 문법 검증, Python으로 카테고리별 학점 합계를 자동 재계산해 졸업요건과 대조.
  - 검증 중 "졸업작품 Ⅱ(캡스톤디자인)" 학점을 잘못 옮겨적은 걸 발견(0학점 → 실제 3학점)하고 수정, 이후 기초교양/융합교양/전공필수 합계가 전부 요건과 정확히 일치함을 확인.
- Supabase에 실제 적재: `db/load_seed_to_supabase.py`(테이블 생성 + 시드 삽입, 재실행해도 안전), `db/verify_seed_supabase.py`(행 수·카테고리별 합계·샘플 데이터로 검증) 작성 및 실행 성공.
  - Supabase의 "Direct connection" 호스트가 IPv6 전용이라 이 환경에서 DNS 연결이 안 되는 문제 발생 → "Transaction/Session pooler" 연결 문자열로 교체해 해결.
- `requirements.txt`에 `psycopg2-binary` 추가, `.env.example`에 `SUPABASE_URL`/`SUPABASE_KEY`/`SUPABASE_DATABASE_URL` 플레이스홀더 추가.

## curriculum_lookup_node: LLM 기반 SQL 조회 노드

- 위 두 Rule이 매칭되면 RAG 대신 Supabase를 직접 SQL로 조회하도록 새 경로 추가.
  - `app/models/schemas.py`: `CurriculumSQLQuery`(LLM이 SQL 문자열만 구조화 출력하는 스키마) 추가.
  - `app/graph/prompts.py`: `CURRICULUM_SQL_PROMPT` 추가 — 두 테이블의 컬럼/타입/FK 관계를 명시하고, "SELECT 단문만, DML/DDL 금지" 규칙과 few-shot 예시 3개를 포함.
  - `app/graph/nodes/curriculum_lookup.py` (신규): SQL 생성 → 안전성 검사(정규식으로 SELECT 단문 확인 + DB 세션을 `readonly=True`로 이중 방어) → 실행 → 결과를 `retrieved_docs` 형식으로 변환.
  - `app/graph/build.py`: `apply_rules` 이후 라우팅에 분기 추가 (`졸업요건_문의`/`교육과정_문의` 매칭 시 `retrieve` 대신 `curriculum_lookup` → `generate`).
  - `app/core/config.py`: `supabase_database_url` 설정 추가.
- 실제 테스트하며 발견해 고친 버그 3개:
  1. LLM이 `requirement_id = (SELECT ...)` 형태의 스칼라 서브쿼리를 조건 없이 써서 "여러 행 반환" 에러 발생 → 프롬프트에 JOIN 방식 few-shot 예시를 추가해 해결.
  2. `RELEVANCE_PROMPT`(intake 관련성 판별)가 "졸업요건/교육과정" 문의를 학사행정 범위로 인식하지 못해 관련 없음으로 걸러내던 문제 → 프롬프트에 해당 주제 명시해 수정. (이 버그 때문에 새 기능이 실제로는 한 번도 도달하지 못하는 상태였음)
  3. SQL 조회 결과값만 근거로 넘기면 `generate_node`가 "3학년 2학기 조건으로 필터링된 데이터"라는 맥락을 잃고 엉뚱하게 "정보 없음"으로 답하던 문제 → 실행한 SQL 자체도 근거 텍스트에 함께 포함해 해결.
